# Security policy

Do not report suspected vulnerabilities in public issues. Use the repository host's private security-advisory channel and include the affected revision, reproduction conditions, impact, and any evidence that can be shared without exposing customer data.

Never include access tokens, passwords, cookies, raw personal data, or production database records in a report. Revoke any credential that was accidentally exposed before continuing the investigation.

The security owner acknowledges a complete report within two business days, establishes severity and containment, and coordinates disclosure after a verified fix is available. Active exploitation, cross-tenant access, credential exposure, publishing without approval, and integrity failures in affiliate attribution are treated as urgent.
